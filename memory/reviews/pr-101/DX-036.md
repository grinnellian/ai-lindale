## Findings by Severity

### Blocker
None.

### Major
None.

### Minor

1. **`--force` blast radius undocumented** — `templates/sme-bootstrap.md:88-89`
   suggests `--force` as an alternative to deleting the stale `tpm.md` override, but
   `install.sh --force` replaces **every** regular-file local override across all
   framework-managed paths (install.sh lines 21–22, 74), not just `tpm.md`. A downstream
   with other intentional overrides (the exact BUG-007 scenario) would have them silently
   clobbered. The adoption-guide takes the safe delete-then-rerun path; sme-bootstrap
   offers `--force` with no warning. Add "(note: `--force` re-links *all* local
   overrides, not just `tpm.md`)" or drop the alternative.

2. **"Any agent type defined in `.claude/agents/`" understates the grant** —
   `.claude/agents/tpm.md:70` and the decisions.md entry describe bare `Agent` as
   opening dispatch to agents in `.claude/agents/`. In practice the bare form also
   exposes the harness's built-in agent types (general-purpose, Explore, Plan, etc.),
   which the old allowlist excluded. The direction of the security argument still holds
   under container-as-boundary — frontmatter is capability declaration, not enforcement,
   and TPM already held Write/Edit/Bash directly — but the widest actual reading of the
   change should be stated where the security reasoning lives (decisions.md), so a
   future reviewer doesn't rediscover it as an unacknowledged delta.

### Nit

1. **Garbled phrasing** — `templates/sme-bootstrap.md:88-89`: "re-run
   `bash .ai-lindale/scripts/install.sh` (or `--force`)" reads as if `--force` were a
   standalone command. Should be "(or re-run with `--force`)".

2. **Step 8 is not a step** — sme-bootstrap Steps 1–7 are actions; Step 8 ("Dispatch Is
   Already Available") requires none. In a numbered procedure an agent may look for an
   action to perform. A non-numbered "Note on dispatch (DX-036)" after Step 7 would be
   cleaner. Cross-references elsewhere ("sme-bootstrap.md Step 8" in decisions.md) would
   need updating if renamed.

decisions.md entry correctly locate enforcement in the container (EPIC-004), classify
frontmatter tool lists as behavioral guidance, and note the allowlist "had no security
value." Consistent with `templates/sme.md`'s own header ("role constraints in agent
prompts are conventions... not a wall"). Only gap is Minor-2 (built-in agent types not
mentioned).

the local `tpm.md` yields the "missing → link" branch; partial real files do not trip
self-host detection (install.sh lines 90–101 explicitly treat a single real file as a
downstream override, not self-host). Both documented paths (delete+rerun, `--force`)
work; `--force` carries the undisclosed side effect in Minor-1.

**Survival through later merges:** Confirmed intact on branch tip despite DX-025,
DX-031, DX-028, DX-027, DX-011, DX-014, and FEAT-013 all touching `tpm.md`. The
"Dispatching project-defined agents (DX-036)" section sits at tpm.md lines 68–70;
later sections were appended around it without clobbering. The bare `Agent` frontmatter
entry also survived DX-029's `maxTurns` and DX-014's `skills` additions.

**decisions.md entry quality:** Good. Dated, ticket-tagged, structured as
Decision/Rationale/Downstream-implication, records the empirical verification that
motivated option 1, cites EPIC-004, and names the downstream project that can now drop
its fork. Matches the register of neighboring entries.

**Residual references sweep:** `grep -rn "Agent(architect, dev)"` finds only
intentional mentions — tpm.md's do-not-reintroduce warning, sme-bootstrap's contrast,
decisions.md's record, and `.claude/commands/autodev.md:38` (DX-039 routing text that

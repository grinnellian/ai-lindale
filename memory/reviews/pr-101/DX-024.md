# Review: DX-024 closure (PR #101)

- **Ticket:** DX-024 — Subagent Permission Inheritance for Research Tasks
- **Issue:** #34 (state: OPEN; PR #101 body says "closes #34")
- **Reviewer:** Claude Reviewer (fable)
- **Date:** 2026-07-06
- **Verdict:** APPROVE-WITH-NITS (verdict applies to the closure decision, not code)

## Closure argument under review

No dedicated DX-024 implementation commits exist. Closure rationale (orchestrator
triage comment on #34): option 3 from the ticket — dedicated read-only research
roles with `gh` access baked in — was delivered by DX-013
(`.claude/agents/researcher.md`, commit c26629e) and FEAT-002
(`.claude/agents/audit-repo.md`, commit 1b65549), both on branch
orchestrate/2026-07-06 and both also closed by PR #101 (#13, #35). Option 2 is
claimed "independently obsolete post-EPIC-004."

## Evidence assessment

**Original pain (from #34 body):** during the 2026-03-22 wickerman-os audit,
3 of 4 research subagents failed — Explore agents lack Bash, general-purpose
agents had Bash denied by permissions, and no agent type combined read-only
`gh` Bash with no write access. TPM had to serialize all `gh` calls itself.

**What exists now on the branch:**

1. `researcher.md` — tools: Read/Grep/Glob/Bash/WebSearch/WebFetch, no
   Write/Edit/Agent, maxTurns 40, explicit `gh issue view`/`gh pr view`
   permission in constraints, and a dedicated "If You Are Running as a
   Subagent" section.
2. `audit-repo.md` — tools: Bash/Read/Grep/Glob, no write tools, maxTurns 30,
   all inspection via `gh api`, never clones. This is precisely the
   wickerman-os-audit use case that spawned DX-024.
3. Both roles are registered as dispatchable subagent types in the live agent
   registry (confirmed in this session's environment).
4. The session permission allowlist (`.claude/settings.local.json`, untracked)
   contains `Bash(gh issue *)`, `Bash(gh pr *)`, `Bash(gh api *)`,
   `Bash(gh run *)`, `Bash(gh auth *)`, `Bash(gh label *)` — subagents inherit
   these, which is what makes the roles' `gh` access frictionless in practice.

**Live verification (ran, not just read):**

- Dispatched an **audit-repo subagent** with two `gh` read commands
  (`gh api repos/grinnellian/ai-lindale`, `gh issue view 34 --json state`).
  Both succeeded, neither was permission-blocked, 2 tool uses, ~8s. The exact
  failure mode from the original dogfooding finding is demonstrably fixed for
  this role.
- Dispatched a **researcher subagent** twice with a minimal one-command smoke
  test. **Both attempts failed at launch: "Agent terminated early due to an
  API error: Prompt is too long."** Not a permission block — the agent never
  got to run Bash. The role's own files are small (agents/researcher.md 4.6KB,
  commands/researcher.md 125B), so the likely culprit is the DX-014
  `skills: claude-api` preload (that bundled skill's reference material is
  large). This is a defect in the DX-013/DX-014 deliverable's subagent path,
  independent of DX-024's permission question.
- Confirmed `scripts/hooks/` no longer exists on the branch (EPIC-004 removal
  is real, supporting the hook-obsolescence half of the triage claim).

**Is the original pain resolved?** Yes, for the scenario that filed the
ticket: TPM can now parallelize external-repo `gh` research through audit-repo
subagents instead of serializing calls itself — verified by running one.
Researcher would double the coverage but is currently undispatchable as a
subagent in this environment.

**What the close leaves unaddressed (deliberately, and acceptably):**

- Options 1 and 2 are not implemented as described, but the ticket says the
  options are "not mutually exclusive," i.e., any one suffices. Option 1
  (scoped-Bash research subagent type) is functionally what the two roles are.
  Option 2 (tool inheritance) is effectively upstream platform behavior now —
  subagents inherit the session permission allowlist, which the live test
  exercised.
- Explore/general-purpose agents still lack the Bash+gh combination. Post
  EPIC-004 that reads as least-privilege by design ("use the dedicated
  roles"), not a gap — but the closing comment should say so explicitly.

## Findings by severity

**Blocker:** none.

**Major:**

1. **Researcher role fails to launch as a subagent** — reproducible 2/2
   ("Prompt is too long"), so half of the cited option-3 capability is broken
   in exactly the dispatch mode DX-024 is about. It does not invalidate the
   closure (audit-repo alone resolves the original scenario, and researcher's
   primary mode is a top-level `--agent researcher` tab), but a follow-up
   ticket must be filed — suspected cause: DX-014 `claude-api` skill preload
   in researcher frontmatter. Closing DX-024 while silently absorbing this
   would misrepresent the delivered capability.

**Minor:**

2. **Triage comment mislabels option 2.** Issue #34's option 2 is "Tool
   inheritance — subagents inherit a subset of the parent's allowed tools."
   Hook-based scoping is DX-010, referenced separately under "Relationship to
   Existing Issues." The EPIC-004-obsolescence claim is true of hook scoping
   but is attached to the wrong option. Outcome-neutral, but this repo is
   explicitly a teaching artifact where the recorded *why* matters — the
   closing comment on #34 should be corrected when the issue is closed.
3. **"No write access" is prompt-enforced only.** Both roles omit Write/Edit,
   but Bash itself is unrestricted (shell redirection, `gh issue create`,
   etc.). Post-EPIC-004 the hard boundary is the container/moat layer, so this
   is consistent with the framework's stated enforcement model — but the
   original ask said "Bash (read-only gh commands) + no write access," and the
   closure should acknowledge the read-only guarantee is soft outside pods.
4. **The enabling `gh` allowlist lives in untracked
   `.claude/settings.local.json`.** Downstream adopters get the agent files
   via install.sh but not the permission rules, so their subagent `gh` calls
   will prompt (or fail in non-interactive runs). Adoption-guide material,
   not a DX-024 reopener.

**Nit:**

5. The closing comment cites no verification evidence. One line ("audit-repo
   subagent verified live against <repo> on <date>") would match this repo's
   documentation standard for closures without implementation commits.

## Disposition recommendation

**Close as resolved-via-alternative (option 3) — the right call**, not
close-as-obsolete (the underlying need is real and was met, not mooted) and
not keep-open (no remainder rises to keeping a permission-inheritance ticket
alive when the practical answer is "dedicated roles + inherited session
allowlist"). Conditions to attach at close time:

1. File a follow-up ticket for the researcher subagent launch failure
   ("Prompt is too long", suspect DX-014 claude-api preload).
2. Amend the closing comment: correct the option-2 mislabel (tool inheritance
   vs. DX-010 hook scoping) and state explicitly that Explore/general-purpose
   agents remaining gh-less is by design.

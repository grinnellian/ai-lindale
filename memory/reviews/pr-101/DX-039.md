## Findings

### Blocker

None.

### Major

- **M1 — Reviewer fallback silently narrows documented current behavior, and the docs mis-state history (violates the letter of AC-2).**
  Pre-DX-039, the REVIEW row read: "architect reviews PR; **dispatch domain reviewers (SME, security, i18n, etc.) as appropriate for what the PR touches**." DX-039 (`ac2adc8`) replaced that discretionary fan-out with config-driven glob matching and states in three places that the unconfigured fallback is unchanged: `autodev.md:33-35` ("review is planner-only — same as today"), row 53 ("falls back to planner-only review when unconfigured"), and `templates/team-config.yml:35-36` ("today's default: … reviewed by `architect` alone"). All three claims are inaccurate — today's documented default included judgment-based domain reviewers. The issue's Proposal ("reviewers … default: empty") supports deterministic config-driven fan-out, but the removal of the TPM's discretionary reviewer dispatch is a real behavior change that AC-2 ("defaulting to current behavior when absent") does not authorize and the text actively mis-documents. Fix: either (a) retain discretion — e.g. "…per the `routing.reviewers` glob matches; the TPM may additionally dispatch domain reviewers (SME, security, etc.) at its discretion" — or (b) keep the deterministic design but correct all three "same as today" claims and note the intentional change in the commit/issue.

### Minor

- **m1 — Diff-command inconsistency between the two files.** `autodev.md:31` specifies matching globs against `gh pr diff --name-only`; `templates/team-config.yml:56` says globs "are matched against `git diff --name-only` for the PR". Bare `git diff --name-only` diffs the working tree, and DX-038's Rules bullet (`autodev.md:113`) mandates three-dot merge-base scope. The template should mirror the command autodev actually prescribes (`gh pr diff --name-only`, or `git diff main...HEAD --name-only`).
- **m2 — Unresolvable-agent fallback is wrong-shaped for the `reviewers` table.** `autodev.md:36-41` applies one rule to "both tables": unresolvable name → "fall back to `architect` and note the misconfiguration". For `planners` that is exactly right. For `reviewers`, the architect (as default planner-of-record) has already reviewed — falling back dispatches a redundant second architect review. The sensible reviewer-side fallback is to skip that entry and note the misconfiguration in the ticket comment.

### Nit

- **n1 — Stale terminology in Rules.** `autodev.md:107` still says "Dispatch independent **architect** reviews in parallel"; post-DX-039 this should be "planner reviews" (the row it governs now routes).
- **n2 — No dedup guidance for reviewer fan-out.** "Dispatch the mapped agent for every matching glob" (`autodev.md:32-33`) can double-dispatch when multiple globs map to the same agent, or when a glob maps to the planner-of-record. One clause ("dedupe agents; skip the planner") would close it.
- **n3 — Upstream lookup path is ambiguous; prefix matching underspecified.** "the project's `team-config.yml`" (`autodev.md:23`) has no root-level referent in this repo (the file exists only as `templates/team-config.yml`, which is a template, not live config) — harmless since absence → default, but worth a word. Prefix case-sensitivity and unprefixed ticket titles are likewise unstated (both fall through "prefix has no entry" only by inference).

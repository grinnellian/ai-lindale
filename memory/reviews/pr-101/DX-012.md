## Findings

### Blocker — none

### Major

**MAJOR-1: `check-file-overlap.sh` silently misses directory containment unless the directory is
given with a trailing slash — and its own comment claims otherwise.**
Verified by running: `check-file-overlap.sh "src/feature" "src/feature/handler.ts"` exits 0
(no overlap reported). The in-code comment (lines 72-73) says containment is detected when
"either path ends with '/' in its original form, **or one path is a prefix directory of the
other**" — the second clause is not implemented; only the `case "$raw_a" in */)` trailing-slash
path exists. Worse, `dev.md`'s instruction to the TPM says only "(comma-separated paths)" and
never mentions the trailing-slash requirement, so an orchestrator following the docs exactly
will get false negatives in the tool's core scenario. Fix: implement prefix-directory
containment for slash-less paths (or check with `-d` / document the trailing-slash contract in
`dev.md` and fix the comment). Silent false negatives are the worst failure mode for a
pre-dispatch safety check.

### Minor

**MINOR-1: No input normalization beyond trailing-slash strip — whitespace and `./` cause false
negatives.** Verified by running: `"src/a.ts, src/b.ts"` vs `"src/b.ts"` exits 0 (the space
after the comma makes ` src/b.ts` != `src/b.ts`); `"./src/a.ts"` vs `"src/a.ts"` exits 0.
Both are natural TPM inputs. Trim whitespace and strip leading `./` in `normalize()`.

**MINOR-2: AC-4's orchestrator-side instruction is placed in the wrong prompt.** The sentence
"a TPM should run `scripts/check-file-overlap.sh`" lives in `dev.md` (the Dev agent's system
prompt); `grep` confirms `tpm.md` and `commands/autodev.md` contain no reference to the script.
CLAUDE.md's pointer is shared context, but the agent responsible for pre-dispatch checking never
gets the instruction in its own role file. The arch plan only listed `dev.md` + `CLAUDE.md`
edits, so the implementer followed the plan — but the gap is real. Recommend a one-line addition
to `tpm.md`/`autodev.md` (fits in this ticket or an immediate follow-up).

**MINOR-3: Convention has no carve-out for non-issue branches — including this branch.**
Verified by running: `validate-branch-name.sh orchestrate/2026-07-06` exits 2, as do the
`worktree-agent-*` merge branches used throughout this repo's actual history. `dev.md` says
"Every issue branch follows..." and CLAUDE.md says "Issue branches follow...", which is
technically consistent (these are not issue branches), but nothing anywhere states which branch
families are exempt. An agent told to "validate branch names" will flag the orchestrator's own
session branch. Add an explicit exemption note (e.g. `orchestrate/<date>` session branches,
`worktree-agent-*` integration branches) to the `dev.md` section.

**MINOR-4: SHARED_CONFIG_FILES does not reflect this repo's actual shared-file traffic.**
This very branch shows `.claude/agents/tpm.md` touched by three parallel-era tickets (DX-011,
DX-014, DX-027). Verified by running: two dispatch lists both containing
`.claude/agents/tpm.md` exit 1 (hard block). Blocking is the safe default (forces
serialization), so this is tuning, not a bug — but the warn-list contains `package.json`
(this repo has none; copied verbatim from the plan) while omitting the demonstrated hottest
shared files (agent definitions). The list is also hardcoded with no team-config.yml override
(DX-005 tie-in, same deferral as AC-3). Worth a note in the DX-005 scope.

### Nit

**NIT-1:** `scripts/tests/test-branch-naming.sh` and `test-file-overlap.sh` lack the executable
bit; every sibling test suite is `-rwxr-xr-x`. Harmless (CI invokes via `bash`), but
inconsistent.

**NIT-2:** Dead code at the end of `check-file-overlap.sh`: `if [ "$WARNING_FOUND" -eq 1 ]; then
exit 0; fi; exit 0` — the conditional is a no-op; `WARNING_FOUND` is effectively write-only.

**NIT-3:** `normalize()` comment mentions remembering directories "via a side list" — no side
list exists (stale comment from an earlier design).

**NIT-4:** Missing second argument to `check-file-overlap.sh` is treated as an empty list and
exits 0 silently (verified). For a safety check, a usage error on argc != 2 would prevent a
TPM quoting mistake from reading as "no overlap."

**NIT-5:** In the validator, the prefix set is encoded twice at different strictness: the regex
accepts any `[A-Z]+` prefix and the case table then constrains it. Works correctly (unknown
types fail with a clear message), but adding a prefix means knowing the case table is the single
source of truth — a comment saying so would help the DX-005 implementer.

## Verdict Rationale

The naming validator is solid: every adversarial input behaved correctly, framing is consistent,
docs are thorough, and the plan adaptation was the right call. REQUEST-CHANGES rests on MAJOR-1:
the overlap checker's containment detection silently fails for slash-less directory paths, its
own comment claims that case is handled, and the TPM-facing usage docs don't disclose the
trailing-slash contract — a silent false negative in the exact scenario AC-4 exists to prevent.
The fix is small (implement prefix containment or document + enforce the contract, plus a test
for the slash-less case). MINOR-1 through MINOR-3 would ideally ride along.

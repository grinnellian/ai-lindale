## Escalation-chain coherence

Chain as implemented: **dev → architect → (fail) → `BLOCKER:` in return summary → TPM applies
`needs-human`/`blocked` → human**; **architect → TPM → (fail) → human via TPM labels**;
**TPM → architect or SME → (fail) → TPM applies labels itself → human**.

- **No dead ends:** every path terminates at the human tier, and exactly one role (TPM) applies
  labels — consistent with DX-030, where the escalation comment is signed `-Claude TPM`.
- **Cycle check:** architect↔TPM mutual dispatch is a potential two-node cycle, but each section's
  "if the peer can't resolve it → human tier" bounds it to one peer round per side, and `maxTurns`
  backstops. Acceptable; noted as NIT-3.
- **Edge case:** dev.md and architect.md both say "don't escalate to the human yourself" and
  delegate label application to "the TPM" — this presumes a parent TPM session exists. In a
  standalone `--agent architect` / `--agent dev` session there is no TPM; benign in practice
  (a human is driving standalone sessions) but the assumption is unstated. NIT-4.
- **Consistency with DX-030:** good. Role sections defer to, rather than restate, the
  `needs-human`/`blocked` semantics; no contradictions found between the three sections and
  autodev.md. Tier-2 correctly happens *inside* the dispatched agent (dev consults architect
  itself), so autodev.md needs no mediation step — coherent with the deviation.

### Minor

- **MIN-1 — AC4 only half-specified.** "Blocked items first" is unambiguous for the end-of-run
  summary (autodev.md:111) but absent from the Startup survey path (autodev.md:5, "survey open
  tickets, summarize their states") — which is precisely the "user returns from AFK and asks
  status" moment the original ticket describes. One clause on the Startup section would close it.
- **MIN-2 — `BLOCKER:` token has no documented consumer.** dev.md instructs flagging `BLOCKER:`
  "in your return summary so the TPM can apply `needs-human`/`blocked`", but neither tpm.md nor
  autodev.md tells the TPM to scan dev return summaries for that token. The original plan had the
  orchestrator parsing the prefix; in the deviated design the parser side went missing. Works by
  inference today; should be one line in autodev.md Rules or tpm.md.
- **MIN-3 — Approved plan's behavioral test plan (Tests 1–8) not executed.** The arch-approved
  plan mandated 8 manual behavioral scenarios (implementation-order steps 4–7). No evidence of any
  run in the commit, issue thread, PR body, or memory trackers. Tier-2 nested dispatch (dev
  subagent dispatching architect via `Agent`) in particular has never been exercised end-to-end.
- **MIN-4 — No closing comment on issue #11.** The thread's last word is the orchestrator's
  "Keeping open for the remainder." The remainder + deviation are documented in the commit message
  and PR #101 body, but not on the issue itself; per DX-028 (issue as authoritative spec), a
  closing comment noting the deviation belongs on #11 before auto-close buries it.

### Nit

- **NIT-1 — Garbled phrase in dev.md:** "a blocker outside your competence gap" reads inverted
  (outside your competence *gap* = within your competence). Should be "outside your competence"
  or "a competence gap" (`.claude/agents/dev.md:89`).
- **NIT-2 — CLAUDE.md overstates the SME path.** "any → SME" — but only tpm.md's section names
  SME dispatch; dev.md and architect.md offer no SME route. Either trim CLAUDE.md to "TPM → SME"
  or add the route to the other roles.
- **NIT-3 — architect↔TPM ping-pong unbounded by explicit rule** (bounded only by each side's
  one-round-then-human logic and `maxTurns`); a "one peer round per blocker" sentence would make
  the bound explicit.
- **NIT-4 — tpm.md SME dispatch has no absent-SME fallback.** This framework repo ships no SME
  agent (`.claude/agents/` has none; SME is a downstream-generated template), and unlike the
  Routing section's explicit fall-back-to-architect rule, the escalation section doesn't say what
  to do when no SME exists.

  post-EPIC-004 architecture is TPM-as-orchestrator via `autodev.md`; DX-036 (#85) lifted the
  `Agent(architect, dev)` frontmatter restriction specifically so any project agent is
  dispatchable by name. Routing Tier-2 through a nonexistent orchestrator file would have been
  cargo cult. The plan's "Consultant" role also no longer exists (superseded by the SME template),
  which the implementation correctly reflects.
- Every substantive element of the original ticket has a live counterpart; the only true residue
  is the Startup-path blocked-first clause (MIN-1) and the `BLOCKER:` consumer line (MIN-2), both
  one-line fixes that do not warrant keeping the ticket open — fix them on this PR rather than
  spawning a remainder ticket.
